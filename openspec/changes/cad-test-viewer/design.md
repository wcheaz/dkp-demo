## Context

The application has a robust `<CadViewer>` component, but it is currently only used within the main design gallery page for generated structures. Developers and designers have no easy way to test external, manually modified, or third-party DXF files in the web UI.

Additionally, the generated DXF files use default CAD colors (white/black lines), which does not help represent materials (wood, concrete, steel) visually. Standardizing layer colors using RGB true colors in the DXF generation pipeline will result in more realistic diagrams.

## Goals / Non-Goals

**Goals:**
- Provide a clean, isolated client-side test route `/cad-viewer` with drag-and-drop or file upload to render any DXF file in the browser.
- Configure specific, natural material-based RGB colors for DXF layers (`Floor_Plan`, `Roof_Outline`, `Trusses`, `Dimensions`) generated by `dxf_builder.py`.

**Non-Goals:**
- Add navigation links to the test viewer from the main gallery page.
- Persist uploaded files on the server or in the database.
- Transition the DXF builder to produce 3D output in this change.

## Decisions

### D1: Client-side Local CAD File Parsing
- **Choice**: Use HTML5 Drag & Drop API / File Input along with the browser's `FileReader` to read local `.dxf` files as an `ArrayBuffer`. Convert this buffer to a base64 string directly in the browser and pass it to the `<CadViewer>` component.
- **Rationale**: This is a client-only solution that does not require any backend API changes, database storage, or server storage. It is secure, fast, and matches the base64 input format that `<CadViewer>` expects.
- **Alternatives Considered**: Creating an upload endpoint on the Starlette backend to parse and send back base64. Rejected due to unnecessary API complexity, network overhead, and security exposure.

### D2: Dynamic Import of CAD Viewer
- **Choice**: Import the `<CadViewer>` component on the test page using Next.js `dynamic` with `ssr: false`.
- **Rationale**: The core `@mlightcad/cad-simple-viewer` uses WebGL and web worker APIs that require the browser environment. Using `ssr: false` prevents compilation or execution errors during server builds.

### D3: Layer Colors via ezdxf True Color (RGB)
- **Choice**: Configure the layer colors in `agent/src/dxf_builder.py` using `layer.rgb = (r, g, b)`.
  - `Floor_Plan`: `(128, 128, 128)` (Concrete Gray)
  - `Roof_Outline`: `(70, 130, 180)` (Steel/Slate Blue)
  - `Trusses`: `(139, 90, 43)` (Timber Brown)
  - `Dimensions`: `(0, 0, 255)` (Annotation Blue)
- **Rationale**: Defining true colors on layer creation ensures the colors are embedded in the DXF file metadata. This ensures that any standard CAD software (including `@mlightcad/cad-simple-viewer` and MiTek Pamir) will render the layers in the designated colors without manual user styling.

## Risks / Trade-offs

- **[Risk]**: Large DXF files uploaded to the browser could cause performance lag or memory crashes during base64 conversion.
- **[Mitigation]**: Limit the uploaded file size to 10MB client-side and display a clear loading state while the file is being read and processed.
