## Why

To automate and streamline the pricing process in structural design software (specifically MiTek Pamir), the generated IFC files must contain richer metadata. This change associates functional structural roles and pricing-relevant attributes directly with generated lumber members (`IfcMember`).

## What Changes

- Classify the functional role of each generated `IfcMember` (e.g. rafter, chord, web, ceiling joist) using the `ObjectType` attribute.
- Attach wood grade and pricing-specific metadata (such as treatment, supply code, or cost attributes) via standard property sets.
- Add code comments for future dynamic property configuration (e.g. wood treatments derived from `DesignParameters`).

### Scope and Rollout Boundaries
- This change applies to all structural timber members generated by `agent/src/ifc_builder.py` for gable, hip, mono-pitch, and flat roof designs.
- All metadata will be statically mapped based on current geometries and default configurations.

### Non-Goals
- Adding pricing metadata to walls (`IfcWallStandardCase`).
- Generating structural connection elements (e.g. nailplates, fasteners).
- Dynamically deriving material treatment or pricing parameters from API inputs in this phase.

## Capabilities

### New Capabilities

*(None)*

### Modified Capabilities

- `ifc-generation-tool`: Extend the requirements to specify that generated timber `IfcMember` elements must have an associated functional classification in `ObjectType` and be populated with standard property sets detailing wood grade and pricing metadata.

## Impact

- **Affected Code**: `agent/src/ifc_builder.py` (specifically `_add_member` and how members are defined/instantiated).
- **APIs**: No changes to the `/api/ifc/generate` endpoint payload or API signature.
- **Dependencies**: No new external dependencies; utilizes standard `ifcopenshell` capabilities.
