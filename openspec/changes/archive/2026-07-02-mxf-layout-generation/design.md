## Context

Currently, the backend generates DXF and IFC files for architectural and structural engineering workflows. To integrate directly with MiTek Pamir (an industry-standard truss design suite), we need to support exporting building wall layouts in the MiTek Exchange XML (`.mxf`) layout format. This enables users to import wall boundaries directly into Pamir, where they can run native auto-framing and plate-stress calculations.

## Goals / Non-Goals

**Goals:**
- Implement a backend layout MXF builder that produces valid XML files mapping the building outer perimeter.
- Position the walls starting from local origin `(0, 0, 0)`.
- Configure wall thickness directions (z-axes) to point inwards to match standard perimeter wall alignment.
- Offset inner wall skins (BackFace) at corners to represent clean joint overlaps.
- Provide a frontend button in [design-component.tsx](file:///home/ncheaz/git/dkp-demo/src/components/design-component.tsx) to download the `.mxf` file.
- Add a future task reminder in [TODO.md](file:///home/ncheaz/git/dkp-demo/hidden/TODO.md) regarding pre-calculated roof and floor surfaces.

**Non-Goals:**
- Generating Fabrication MXF data (joint plates, member cuts, CNC codes) which is too complex for backend calculation.
- Calculating or exporting `<SurfaceList>`, `<RoofList>`, or `<FloorList>` nodes in this phase (omitted per user instructions).
- Providing 3D rendering support for MXF files in the web CAD viewer (which remains scoped to DXF/IFC wireframes).

## Decisions

### 1. XML Construction using ElementTree
- **Approach**: Use Python's built-in `xml.etree.ElementTree` to build the XML structure programmatically. For clean readability, format the output bytes using `xml.dom.minidom.parseString(xml_str).toprettyxml(indent="  ")`.
- **Rationale**: Keeps the codebase lightweight and avoids external library overhead. Standard XML serialization ensures strict compatibility.

### 2. Wall Alignment and Direction Vectors (Inward Projection)
- **Approach**: Position the walls clockwise around the floor plan box starting at `(0, 0, 0)` with the local Z-axis (thickness direction) pointing inward:
  - **W0** (Bottom, Y=0): Origin `(0, 0, 0)`, running axis (xAxis) points east `(1, 0, 0)`, thickness axis (zAxis) points north `(0, 1, 0)`.
  - **W1** (Right, X=W): Origin `(W, 0, 0)`, running axis (xAxis) points north `(0, 1, 0)`, thickness axis (zAxis) points west `(-1, 0, 0)`.
  - **W2** (Top, Y=D): Origin `(W, D, 0)`, running axis (xAxis) points west `(-1, 0, 0)`, thickness axis (zAxis) points south `(0, -1, 0)`.
  - **W3** (Left, X=0): Origin `(0, D, 0)`, running axis (xAxis) points south `(0, -1, 0)`, thickness axis (zAxis) points east `(1, 0, 0)`.
- **Rationale**: Aligning the thickness direction inwards matches the reference [Test Project 2.mxf](file:///home/ncheaz/git/dkp-demo/hidden/Sample_Project/Test%20Project%202.mxf) and prevents the walls from shifting outward beyond the building boundary.

### 3. Wall Skin Corner Offsets (Shortening)
- **Approach**: Set `FrontFace` skin polygons from `0` to `length`. Set `BackFace` (inner skin) polygons to start at `thickness` and end at `length - thickness` (e.g. `0.2` to `length - 0.2`).
- **Rationale**: Replicates the corner overlapping logic observed in Pamir exports. Shortening the inner faces prevents inner skins from intersecting at the corners.

### 4. REST API Endpoint and Model Extension
- **Approach**: 
  - Add `/api/mxf/generate` POST endpoint in [main.py](file:///home/ncheaz/git/dkp-demo/agent/src/main.py) which returns the generated bytes with content-type `application/mxf`.
  - Add `mxfContent` (as optional base64 string) to [types.ts](file:///home/ncheaz/git/dkp-demo/src/lib/types.ts) and [agent.py](file:///home/ncheaz/git/dkp-demo/agent/src/agent.py) models.
  - Expose the `generate_mxf` backend tool in [agent.py](file:///home/ncheaz/git/dkp-demo/agent/src/agent.py) and hook it up in [page.tsx](file:///home/ncheaz/git/dkp-demo/src/app/page.tsx).
- **Rationale**: Mimics the architecture used for DXF and IFC downloads, maintaining system consistency.

## Risks / Trade-offs

- **[Risk] Pamir Import Errors if XML namespace/headers vary**
  - *Mitigation*: Ensure the generated root `<Mxf>` matches the schema, namespace attributes, and version markers of the reference files exactly.
- **[Risk] Missing Surfaces require manual user generation**
  - *Mitigation*: Pamir's import wizard allows users to auto-generate roof surfaces in one click (Automatic Surface) when wall boundaries are defined.
