## Why

Currently, the generated IFC file exports structural timber members (`IfcMember`) without any associated material data. Providing material information (e.g., that these elements are made of specific wood/lumber material) is crucial for downstream BIM applications (like MiTek Pamir) to perform proper structural analysis, scheduling, and visualization.

## What Changes

- Add predefined material data assignment to all structural timber members (`IfcMember`) generated by the IFC builder.
- Define an `IfcMaterial` entity representing the timber material (e.g., `"Timber - C24"`).
- Link the material to the generated `IfcMember` objects using `IfcRelAssociatesMaterial`.
- Add documentation/comments in the codebase explaining how material configuration could be made dynamic or variable in the future (e.g. via design parameters or user inputs).

### Non-Goals

- Dynamically changing the material based on user inputs or design parameters in this phase.
- Supporting materials for other structural items (like walls) in this change.
- Creating physical material layers or finishes.

## Capabilities

### New Capabilities

*(None)*

### Modified Capabilities

- `ifc-generation-tool`: Extend the requirements to specify that generated timber `IfcMember` elements must have an associated `IfcMaterial` representing their lumber type.

## Impact

- **Affected Code**: `agent/src/ifc_builder.py` (specifically [_add_member](file:///home/ncheaz/git/dkp-demo/agent/src/ifc_builder.py#L147) or how it associates materials to the created members).
- **APIs**: No changes to the `/api/ifc/generate` endpoint payload or API signature, as materials will be statically predefined at this stage.
- **Dependencies**: Uses `ifcopenshell` which is already included in dependencies.
