# MXF Builder API Reference

Function signature, parameter mapping, and output shape for the backend Layout MXF (MiTek Exchange XML) export used to import wall layouts into MiTek Pamir.

## API Endpoint

- **Path:** `/api/mxf/generate`
- **Method:** `POST`
- **Body:** JSON object containing `DesignParameters`

Returns a UTF-8 Layout MXF XML byte stream with `Content-Type: application/mxf` and a `Content-Disposition: attachment; filename="design.mxf"` header.

## Function Signature

```
build_mxf(params: Any) -> bytes
```

Implemented in `agent/src/mxf_builder.py`. Consumes a `DesignParameters`-like object and emits a Pamir-compatible Layout MXF document describing the four outer building walls.

## DesignParameters Field Mapping

| Field | Required | Format | Example |
|-------|----------|--------|---------|
| `floorPlanDimensions` | yes | `"<W>x<D>m"` | `"10x15m"` |
| `buildingType` | no | free text (used as batch/job name, defaults to `"Building"`) | `"Residential"` |
| `roofType` | no | ignored for wall layout (reserved for future surface generation) | `"gable"` |
| `roofPitch` | no | ignored for wall layout | `30` |
| `overhang` | no | ignored for wall layout | `"0.5m"` |
| `location` | no | ignored for wall layout | `"Bratislava"` |

`floorPlanDimensions` is the only minimum required field. If missing, malformed, or non-positive, `build_mxf` raises `ValueError`.

## Output Format

- **Schema:** MiTek Exchange XML (Layout MXF), `version="MXF Version 5.11"`
- **Coordinate system:** metres, building placed at local origin `(0, 0, 0)`
- **Wall geometry:** 4 outer walls (`W0`..`W3`) traced clockwise around the floor-plan rectangle
- **Thickness direction:** each wall's Z-axis points **inward** toward the building centre (standard Pamir perimeter convention)
- **Wall thickness:** `0.2 m` (fixed, mirrors the reference export)
- **Wall height:** `3.0 m` (fixed, mirrors the reference export)
- **Skin corner offsets:** `FrontFace` spans `0..length`; `BackFace` (inner skin) is shortened to `thickness..(length - thickness)` to keep corner joints clean
- **Encoding:** UTF-8, pretty-printed with 2-space indent via `xml.dom.minidom`

## Omitted Nodes (Phase 1 Non-Goals)

The following nodes are intentionally **not** emitted in this phase (see `openspec/changes/mxf-layout-generation/design.md` non-goals):

- `<SurfaceList>`, `<RoofList>`, `<FloorList>` — roof and floor surfaces must be auto-generated by the user inside Pamir's import wizard (one-click "Automatic Surface").

## Frontend Tool

The agent exposes the `generate_mxf` client-side tool (registered in `src/app/page.tsx`), mirroring `generate_dxf` and `generate_ifc`:

- **Parameters:** `design_id` (number, required)
- **Behaviour:** POSTs the design's cleaned parameters to `/api/mxf/generate`, base64-encodes the returned bytes, and stores the result in `mxfContent` on the matching `DesignEntry`.
- **UI:** A `MxfDownloadButton` is rendered next to the IFC download button in `design-component.tsx` whenever `mxfContent` is present.

## Auto-Trigger Rule

MXF generation fires automatically when design status is `"complete"` (all 4 desirable fields present). The agent calls `generate_mxf` with the current design ID; no explicit user request is needed. This mirrors the auto-pricing, DXF, and IFC generation behaviour.
